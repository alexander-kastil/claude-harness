# Working on the extension

- Load the global `vscode-extension` skill before the first edit of `media/` or `src/`. Bump and install is its `scripts/sideload.ps1 -Repo <repo>` (a patch bump on every install). Semantic versioning is set once per release, without asking: the release's version follows the last released one, `patch` when the release only fixes or polishes, `minor` when it adds a user-visible feature (a page, tab, control, command or setting), `major` when it removes or breaks one (a command, a setting, a stored-state or message shape); a look at a webview change is its `references/design-preview.md`; chart shapes the owner settled are in its `references/webview-charts.md`.
- Release 0.6.5 (owner, 2026-10-26): every change made on 2026-10-26 goes into 0.6.5. `package.json` is set to 0.6.5; sideload with `-NoBump` so no install moves it past 0.6.5.
- Work on this extension belongs to the `vscode-ext-specialist` agent. Kept on the main thread, an implementation turn puts its open questions (callers, CSS rules, signatures) into one fact-gatherer brief before the first edit and reads only the files it edits: the delegation mod denies the fourth main-thread lookup of a turn.
- Edit source with the Edit tool. Never edit through a Bash heredoc (`python - <<'EOF'`, `sed` with escapes): it rewrites `\n` and fails on CRLF files. Scratch and test scripts that hold a backslash (a regex like `/[\\/]/`, a Windows path literal) go through the Write tool too: a heredoc here collapses `\\` to `\`, so the test checks a different regex than the code has.
- Skill sources (`src/distributor.ts`, `src/dist-host.ts`, `src/skill-lock.ts`) install into `.claude` only: real folders in `~/.claude/skills`, repo links as junctions to them, the record in `~/.claude/.skill-sources.json`. The skills CLI's `~/.agents` folder and lock file are read, never written (`tasks/lessons.md`, "Skill sources install into .claude").
- Give Node Windows paths with forward slashes, from a script file, not `node -e` with escaped backslashes.
- What the extension mirrors from Claude Code (session names in `/resume` order in `src/sessions.ts` `sessionTitle`, the `/rename` records in `renameSession`) is read from Claude Code's compiled binary, `@anthropic-ai/claude-code/bin/claude.exe` under the npm global folder, with `grep -aoE '.{300}<pattern>.{300}'`. That lookup needs a shell: a read-only haiku general-purpose agent, never the fact-gatherer (`tasks/lessons.md`, "Session names mirror /resume").
- Run the UI suite on a new root every time: `UI_ROOT=<scratchpad>/uiroot-<n> npm run test:ui`. The default root `%TEMP%\claude-harness-ui` keeps the usage index and workbench layout of earlier runs, and on it "before the index exists ..." and "the command bar stays within two rows at a 640 px page" fail (65/68 there, 68/68 on a fresh root, 2026-10-25).
- The owner's history of corrections is in `tasks/lessons.md`; read the entries for the view you are about to change.
- The webview script is `src/webview/*.ts`, bundled by `npm run webview` (part of `npm run compile`) into `media/panel.js`, which is generated and not in git: never edit it. Messages between host and webview are typed in `src/shared/messages.ts`; change a message there first. A module still starting with `// @ts-nocheck` is unchecked; removing the line switches it on.
- Every tooltip in the webview uses the house hover card (`.hc` in `.tl-hover`, shown with `placeCard`). A plain hint is a `title` attribute: the delegated handler in `src/webview/hover.ts` (`showTip`) renders it as the card, with the element's own codicon in the head and lines after the first as text. A hint with a heading and a sentence uses `tabTip(label, glyph, text)`. Never a native browser tooltip and never a separately styled one.
- Actions that start Claude sit in an AI group: a button group like the others, led on the left by the Claude mark (`claudeMark()` in `src/webview/dom.ts`) as a marker that is not a button, followed by each action as a button with its own icon. Never two buttons with the same Claude mark, and a lone Claude action gets the same group, so the pattern is recognizable everywhere (owner, 2026-10-25). Native VS Code menu commands use `media/claude-mark-light.svg` and `-dark.svg`. Plugin install, uninstall and rename marketplace only run the CLI and keep their own icons. The generic webview UI rules are the vscode-extension skill's `references/webview-ui-rules.md`; this repo's own conventions are in `tasks/lessons.md` ("Repo UI conventions from 0.4.0" and "from 0.5.0": bylines, table tokens, the detail info card, the billing labels).
