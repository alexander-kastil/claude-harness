# Plugins and marketplaces

Plugin Hunter builds a plugin from skills and agents; the marketplace commands list, check and rename
marketplaces and update an installed plugin. Writing commands run for real unless `--dry-run` is given.

| Command | Returns (`--json`) |
| --- | --- |
| `hunt catalog` | `{catalog, markets, strays, applied}`: the skills and agents across Global and repos, the marketplaces (owned ones can take a plugin), and `strays: [{scope, path, why}]`, the folders under a skills root with no SKILL.md (the `synced` folder under `~/.claude/skills` is not one); `skills remove --name <folder> [--repo <dir>]` retires one |
| `hunt plan ...` | the same as `hunt create --dry-run` |
| `hunt create --name <p> --skills a,b --agents x,y [--category <c>] [--market <m>] [--description <t>] [--retire]` | `{name, market, problems, files, retired, kept, check, source, dir, installed, backup, applied}`; `check: [{file, line, text}]` is every line in CLAUDE.md, `.claude/rules/`, skills and agents of Global and the repos, and in the market's plugins, that still names a retired copy by its old place or bare name (a `plugin:name` mention and the element's own files are left out); only reported, never rewritten, empty without `--retire`. A copied skill's own absolute path (`~/.claude/skills/<name>/`, `$HOME/...`, `%USERPROFILE%\...`, `C:\Users\<u>\.claude\skills\<name>\`) in its Markdown becomes `<this skill>/` in the plugin copy (a `files` row `... (N absolute paths to <this skill>/)`); a path into another skill, or the own path in a script, is a `check` row; the same in `hunt add` |
| `hunt add --name <p> [--skills a,b] [--agents x,y] [--market <m>] [--retire] [--dry-run]` | `{name, market, problems, files, retired, kept, check, version, installed, backup, applied}`; copies the items into a plugin an owned marketplace already lists (without `--market`, the one that lists it) as `hunt create` copies them, bumps the patch version in plugin.json and the catalog entry where either carries one (`version`, null when none does) and in the marketplace folder's `package.json` and `package-lock.json` when their version was the plugin's (listed in `files`), updates the plugin when it is installed (`installed` is its key, else null), and with `--retire` retires the copies like `hunt create`; an item the plugin already has is a `problems` row (exit 1), never an overwrite; a failed update takes the copies and the bump out again and retires nothing |
| `hunt create\|add ... --skills <plugin>:<name> --agents <plugin>:<name>` | with `hunt create` or `hunt add`: takes the element out of another plugin of the same directory marketplace instead of Global or a repo; it is copied as usual, then removed from that plugin (backed up, a `retired` row `skill <name> in plugin <plugin>`), that plugin's patch version is bumped with the same rules (rows in `files`) and it is updated when installed, after the target; a failed install or update puts the files of both plugins back and returns Claude Code to its state before (a new plugin uninstalled, an updated one installed again); `check` lists the mentions of the old `<plugin>:<name>` |
| `hunt create ... --files <file>=<path in plugin>,... [--drop-files]` | with `hunt create`: also copies a hooks.json, a hook script or an `.mcp.json` into the plugin (a plugin may be made of these alone). A hook module (listed under `modules` by a ride-along hooks.json, or a script given as `hooks/<name>.mjs`, `.js` or `.ts` beside one) lands at `mods/<name>/<file>` with the files it imports by relative path, and `hooks/hooks.json` is written with `"modules": ["../mods/<name>/<file>"]`; a command-hook hooks.json and an `.mcp.json` stay where placed, and the dry-run `files` rows show the final paths; `--drop-files` retires the ones under `--root`, backed up first; `--market` takes the marketplace name or its folder |
| `marketplaces` | `{marketplaces: [{name, kind, source, location, plugins, installed, enabled, updates}], problems: [{marketplace, plugin, problem, installed, source}], applied}`; `problem` is `Update available` or `Enabled, not installed` |
| `marketplaces rename --from <name> --to <name> [--dry-run]` | `{from, to, kind, changes: [{file, detail}], commands: [string], applied}`; rewrites the catalog and the settings that name it, and lists the `claude plugin marketplace` commands that re-register it; only a directory marketplace, exit 1 for an unknown `--from` or an existing `--to` |
| `plugins rename --from <plugin>@<market> --to <name> [--repo <dir>]... [--repos a,b] [--dry-run]` | `{from, to, market, changes: [{action, file, detail}], commands: [string], backup, applied}`; renames the plugin folder, its plugin.json `name`, the catalog entry's `name` and `source`, the dependencies and `enabledPlugins` keys that name it, and rewrites `<old>:`, `<old>@<market>` and `plugins/<old>/` in the md files of Global, the repos and the marketplace, each file backed up first; the same three forms are rewritten in the plugin's own `.json`, `.mjs`, `.ts`, `.js` and `.py` files, and in a Markdown file beside the plugin folders (the marketplace's plugin list) `[<old>](<old>)` and a link target `](<old>/...)` become the new name; bare mentions of the old name come back as `check` rows `still mentions <old> N times, lines a, b`; when the catalog already names the plugin `<to>` (a second run after the rename), only the text, dependencies and settings left over are finished, exit 0; the `claude plugin validate`, `marketplace update`, `uninstall` and `install` commands are listed, never run; only a directory marketplace, exit 1 for an unknown `--from` or an existing `--to` beside it |
| `sync plugin --name <plugin@market> [--dry-run]` | `{plugin, market, installed, source, action, applied}`; `action` is `current`, `would update` or `updated` |

`hunt create` writes `plugins/<name>/` with `plugin.json`, the skills and agents (`plugins/<category>/<name>/`
only in a marketplace that already keeps category folders, where `--category` is required; elsewhere it is dropped), adds the
entry to the marketplace's `marketplace.json`, installs `<name>@<market>` for the user, and with
`--retire` retires every copy of the chosen items (backed up under `~/.claude/repo-sync-backups/<stamp>/`).
A repo whose `CLAUDE.md` keeps its copies stays; `kept` says why. If the install fails, the plugin
folder and its marketplace entry are removed again and nothing is retired.
