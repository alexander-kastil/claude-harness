# Mod gotchas and their fixes

| Symptom | Cause | Fix |
| --- | --- | --- |
| Validate: "takes a reference whose plugin and key are string literals" | A state ref built from a variable (`{ plugin: PLUGIN, key }`) | Write `{ plugin: "my-mod", key: "k" }` literally, in a `const` of the file |
| A held tool call runs anyway after ~10 s | Every hook has a 10 s budget of its own time; a `$.clock.sleep` poll spends it | Wait inside a `$` call, which costs no budget: `await $.ui.ask(question, { options: ["Proceed", "Cancel"] })`. It rejects in `-p` runs: deny there |
| The guarded command ran though the hook errored | A hook that throws is skipped and `next(e)` runs for it (fail open) | Make UI calls best effort (`.catch(() => {})`), keep the deny path free of calls that can throw, and put a `finally` cleanup in its own `.catch` |
| Your band line hides another mod's, or theirs hides yours | An `AbovePrompt` hook that returns its own tree without `next(e)` replaces the chain | `const below = await next(e)` first, then return `Box({ flexDirection: "column", children: below ? [mine, below] : [mine] })` |
| A mod's band never shows, even while its own render condition holds | Another installed mod's `AbovePrompt` hook above it returns its own tree without awaiting `next(e)` (prompt-cache-control 0.1.0 hid the orchestration band while agents ran, 2026-10-29; the first diagnosis blamed the band's own condition) | Before debugging the missing band, grep every installed mod's `AbovePrompt` hook for a return that skips `next(e)`, fix that mod as in the row above, and add a `ui.render` stub beneath it in its tests |
| Validate: plugin name "is reserved" | Plugin names may not start with `claude-`, `anthropic-`, `anthropics-` or `cc-plugin-`, be `claude`, `anthropic`, `anthropics`, `claude-code` or `claude-mods`, or put `official` beside `claude` or `anthropic`; the marketplace name is not checked (`harness@claude-harness` passes) | Name it for what it does (`learn-loop`, not `claude-learn`); the skill inside may keep its name. Run `claude plugin validate` on the proposed name before a rename sweep: on 2026-10-28 `claude-harness` was refused after the rename had reached 27 repos |
| `$.command.run({ command: "x" })` misses a skill shipped in a plugin | Plugin skills are named `<plugin>:<skill>` | Resolve through `$.command.list()`: an exact `x`, else a name ending in `:x`. Match `command.run` and `Skill` hooks the same way |
| `claude plugin list` shows `<name>@skills-dir: ✘ Not loaded — the name is already taken` | A plugin folder left in `~/.claude/skills/<name>` from before the marketplace install | `diff -rq --strip-trailing-cr` it against the marketplace folder, then delete the skills-dir copy |
| `$.command.run` starts the `~/.claude/skills/x` copy, never the plugin's `<plugin>:x` | The same skill ships in a plugin and sits in `~/.claude/skills/`; an exact-name match wins over the `:x` suffix match | Keep one source per skill, or accept that the skills-dir copy runs; check with `claude plugin list` and `$.command.list()` |
| A session viewer (claude-harness's Mods view) cannot tell which mod wrote a line | The transcript records a hook only as an attachment (`hook_additional_context` with `hookName`, `hookEvent`, `content`; `hook_success`, `hook_system_message`, `hook_blocking_error`, `hook_non_blocking_error`) and a `{ deny }` as an `is_error` tool result wrapped in `<tool_use_error>`; none of them names the plugin | Open every context line, message and deny reason with `<plugin-name>: `; the viewer groups by that prefix. A plugin that also writes an event log (`.claude-plugin/harness-events.json`) puts the same verbatim text in the event's `detail`, so the viewer drops the transcript copy |
| Mod needs a skill or another plugin | Not installed for other users | `"dependencies": ["other-plugin"]` in plugin.json; it installs from the same marketplace |
| Thresholds people want to change | Constants in the module | `"userConfig": { "everyMinutes": { "type": "number", "title": "...", "description": "...", "default": 5 } }`; read from `register(on, options)` |
| Prompts from peers or task notices counted as the user | `prompt.submit` fires for every origin | Check `e.origin.kind`: `composer`, `bridge`, `sdk` are the user; `peer`, `task-notification`, `plugin` are not |
| A digit hotkey does nothing | Letters only work while the band or pane holds focus; two band buttons with one digit clash | Use a digit for a band `Button` (works from an empty prompt) and give each mod its own digit |
| Timers to test | Real time in tests | `const clock = mock.clock(on, { now })`, then `await clock.advance(ms)`; `$.clock.after`/`every` fire on the way |
| Text assertions on a mounted band | Element props are not plain strings | `await ui.findAll({ type: "Text", text: /regex/ })`, `await ui.press({ key })` for a `Button` |
| Python or bash patch scripts break on regex backslashes in Git Bash | Heredoc and `\b`/`\s` escaping | Write the patch script with the Write tool, or edit with Edit; never inline regex-heavy Python in a heredoc |
| `"\n"` inside a JS string became a real line break; validate says "Unterminated string constant" | Python in a Bash heredoc writing JS turns `\n` into a newline | Same fix: Edit or Write only, never a heredoc patch for JS or TS |
| `$.ui.ask` dialog is one bold paragraph, no option descriptions, no room for the full command | `ask` takes only labels, a `header` (12 chars) and the question text | Also hook `on("ui.render", { component: "AskUserQuestion" })`: match your ask by its `header`, then `next({ ...e, props: { ...e.props, questions: [{ ...q, options: [{ label, description, preview }], multiSelect: false }] } })`. Keep the labels identical to the ask's, since the answer is the drawn label; an invalid rewrite draws the original |
| Test: `$.ui.mount is not a function` inside a stub hook | The hook's own `$` shadows the test's `$` | Name the hook parameter `_` and call the outer test `$`. To assert a render rewrite, a test `ui.render` hook on the component captures `e.props` (it runs beneath the mod) |
| Pushed change does not reach sessions after `/plugin update` | Installs are cached per version in `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>`, a directory-source marketplace too | Bump `version` in the mod's `plugin.json` with every shipped change, then `/plugin update <plugin>@<marketplace>` and `/reload-plugins`. The CLI (2.1.304) reads a directory-source plugin from its folder instead (`claude plugin list` shows `Read from:`): edits load at the next session or `/reload-plugins`, and `claude plugin update` acts only on a version bump; never judge what the CLI runs by diffing the cache |
| Validate: "the const <ref>, read as the reference of a $.state.get call, is also written through, handed on" | A state ref passed into a helper (`get($, statsRef)`) | Pass a string key and switch to literal calls inside the helper: `key === "stats" ? $.state.get(statsRef) : ...` |
| A log or progress file is never written and nothing says why | A path helper took two arguments and was called with four, and the write sat in `try {} catch {}` | Make path helpers variadic, and test that the file appears; a swallowed error in a logging path hides every bug behind it |
| A gate on Edit/Write never fires though the agent clearly wrote files | The agent wrote them with one Bash heredoc (`cat > f <<EOF`), so no Edit/Write call happened | Classify a Bash command that redirects, uses `tee`, `sed -i`, `cp`, `mv` or `Set-Content` as an edit, and take the redirect targets (with `$VAR` expanded from assignments in the command) as its paths |
| A Bash path never matches the repo root on Windows | Git Bash writes `/d/repo/...` while `$.session.root()` is `D:\repo` | Normalise `/x/` to `x:/` and backslashes to `/` before comparing, case-insensitively |
| Headless test run (`claude -p --permission-mode acceptEdits`) leaves files missing | acceptEdits still refuses writes under `.claude/**` and to `.mcp.json` as sensitive paths | Use `--permission-mode bypassPermissions` for a scripted test student in a throwaway lab folder |
| A cheap precheck model waves violations through | It saw only rule headings and was asked whether the action "plainly" breaks one | Give it the full rule text and bias it: "clean only when certain, otherwise suspicious"; a false suspicious costs one strong-model call, a false clean loses the catch |
| State in `$.store` or a shared file is lost when two sessions run at once | Each session cached the value at start and wrote its whole copy back | Read the file fresh, apply the delta and write inside one update call; never write back a copy read at session start |
| An eval of a learning mod drifts between runs | Learner state from earlier runs (mastered rules, feedback) changed what the mod does | Reset that state to empty before each eval run and restore the user's copy afterwards |
| Test: an `fs.read`/`fs.list` stub never matches its fixture path | The engine hands the stub Windows paths (`D:\repo\...`) even when the module passed `/`, and resolves a relative path against the plugin folder `claude plugin test` runs in, not the `cwd` given to `$.session.start` (`demos/x.pptx` arrived as `D:\...\slide-quality-plugin\demos\x.pptx`, 2026-10-22) | Normalise in the stub: `const norm = (p) => p.replace(/\\/g, "/")`, then key fixtures by the path's tail (`s.match(/(?:^|\/)((?:demos|\.claude)(?:\/.*)?)$/)?.[1]`); a stub that throws on a miss shows as `hook was skipped: ENOENT` and the module then reads the real disk |
| Test: `prompt.compose` hook "skipped: next() passed an argument with no { promptModel }" | `$.prompt.compose()` from a test fills nothing in | Pass the whole input: `model`, `promptModel`, `surfaces`, `tools`, `outputStyle: null`, `traits: []`, `sections: []` |
| Test: `turn.complete` hook "skipped: next() passed an argument with no { answer }", the stub "returned no { text }"; `prompt.submit` "no implementation" | `$.turn.complete()` and `$.prompt.submit()` from a test fill nothing in, and nothing beneath the plugin answers them | Pass `{ answer: "ok" }` (plus `agentId` for a subagent's turn) to `$.turn.complete`; stub `on("turn.complete", (_$, e) => ({ text: e.answer ?? "" }))` and `on("prompt.submit", (_$, e) => ({ text: e.text }))` (git-flow-plugin, 2026-10-29) |
| tsc TS5097 on `import ... from "../hooks/x.ts"` in a test | The type-check config does not allow `.ts` suffixes | Import extensionless (`"../hooks/x"`); `claude plugin test` resolves it |
| A `.catch` handler reaches for `next.result` | No such field: `next` in a catch handler is replay-safe | `.catch(($, e, next) => next(e))` fails open, and re-runs nothing beneath when the hook had already called `next` |
| Model needs a hint per prompt without changing what the user typed | Rewriting `text` shows in the transcript | `next({ ...e, context: [...(e.context ?? []), line] })` attaches a block the model reads and the user never sees |
| A countdown in the band stays frozen | A band redraws only on events | `ticker = $.clock.every(1000, () => $.ui.invalidate("ui.render"))` while armed, cancelled with the timer |
| A gate on a named agent stops firing after the agent moved into a plugin | The agent's type became `<plugin>:<agent>` (`image-artist:image-producer`) and the gate compares names exactly (`Set.has(e.subagent_type)`) | Match the bare name: `/(^\|:)(image-producer\|motion-designer)$/` or `NAMES.has(type.split(":").pop())`, and add a test with the prefixed name (brief-check, now the creative check of agent-control-plugin, 2026-10-27) |
| Steer a subagent spawn | `agent.spawn` input | Rewrite `subagentType`, `model` or `prompt` through `next({ ...e, ... })`, or return `{ deny }` (the reason reaches the model); a `workflow` agent can only be denied. Plugin agents are typed `<plugin>:<name>` |
| Test: a stub of a `$` call returns a bare value and the hook gets "not a result object" | The test kit expects `{ value: x }` from a `$`-call stub (`model.complete` too) | Return `{ value: ... }` from every stub of a `$` call |
| A drawn band or pane shows only text in VS Code | `claude` run in VS Code's integrated terminal is surface `terminal`; only the desktop app, the VS Code extension panel (`vscode`) and mobile draw `Svg` | Branch on `e.surface !== "terminal"`, not on `"Svg" in ui` alone: under `claude plugin test` a terminal render also answers `"Svg" in ui` true. Keep a `Text` fallback for the terminal |
| A press inside an `Svg` row does nothing | `Svg` is a leaf drawn as an image (or a script-less frame with `isInteractive`) | Put the `Button` beside the `Svg` in a keyed `Box`; give every `Svg` an `alt` (required) and keep `source` under 131072 characters |
| Test: `TypeError: on("ui.render") after the test first called $` | A render stub was registered after `$.session.start(...)` | Register every `on(...)` stub, render stubs included, before the test's first `$` call |
| Test: `cannot import "node:fs" (from hooks\x.mjs): a hooks module imports its own files by relative path and "claude-code", nothing else` | A hooks module has no Node; every file it imports is held to the same rule | Keep the pure part in a relative `.mjs` with no imports and import it from the module; put Node code (fs, a CLI) in `scripts/`, outside the hook graph, importing `../hooks/x.mjs`. One copy serves both (agent-control-plugin `hooks/route.mjs` and `scripts/route.mjs`, 2026-10-27) |
| Validate refuses a second entry in `hooks.json`; the engine refuses a second `session.start` without a matcher | One module per plugin, one unmatched `session.start` | Put new hooks in their own file, import it from the existing module, and call it from that module's `register` and its `session.start` (the harness plugin's `harness-mentions.mjs`) |
| `prompt.autocomplete` rows never show after a space | The event fires only for a non-empty token at the cursor | Rows come once the first letter of the next word is typed; test and record with partial words (`/harness agents r`), never a trailing space |
| A mod in a directory-marketplace plugin breaks running sessions mid-edit | Sessions read the plugin live from its folder and reload on each change | Write the new code completely in its own file first and wire it into the module last, in one edit |
| Plugin agent types vanish from a running session after plugin folders moved | The registry still points at the old paths | `claude plugin marketplace update <market>`, then `/reload-plugins` in each running session |
| A tool reading a plugin's newest files gets an old copy | `installed_plugins.json` points at the version cache, which lags the directory marketplace source | Prefer the directory source and fall back to the cache (claude-harness `pluginDirs(root, true)`, first copy that has the file) |

## Drawn surfaces

- The desktop app draws an `Svg` as an image. Given a `width` guessed from `bodyColumns`, it overflows
  the slot, keeps its own font and has no padding. Build panes from `Box`/`Text` (padding, borders,
  `wrap: "truncate-end"`) and keep `Svg` for fixed-size icons. `BoxProps` has no `flexBasis`: use
  `width: "50%"` with `flexGrow`/`flexShrink` for equal columns.
- The desktop app loads plugins from `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>`, so an
  uncommitted change under an unchanged version never reaches it. Sync or bump, then a new session.
- The VS Code extension's chat panel runs hooks but draws no panes or bands.
