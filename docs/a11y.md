# Accessibility

Claude Harness is optimized for accessibility. Every page of the panel was scanned for WCAG 2.1 AA problems in a light and a dark theme, every page type was walked with the keyboard alone, and what those checks found is fixed. This page says what was checked, what was fixed and what is left.

## What was checked

| Check | How | Scope |
| --- | --- | --- |
| WCAG 2.1 AA scan | The axe-core engine ran in a real VS Code window over the panel, with the WCAG 2.0 and 2.1 level A and AA rules plus the best-practice rules. | The overview, all 160 navigation pages and the first detail page of every list, in Default Dark Modern and Default Light Modern. 192 pages per theme. |
| Keyboard-only walk | Real key presses (Tab, Shift+Tab, Enter, Space, Escape and the arrow keys, Home and End in the navigation tree) sent to the window. No mouse. | The overview and one page of every page type (65 types) plus the detail page of every list, in both themes. |

The keyboard walk checks, on every page:

- Every control can be reached with Tab, and every control that looks clickable can take focus.
- Tab moves through the page in reading order and leaves it without a trap. Shift+Tab goes back.
- Each focused control shows a visible focus indicator.
- Enter and Space open a list row or a tile, and focus does not end up on nothing afterwards.
- Escape does not drop focus.
- In the navigation tree, the arrow keys, Home and End move the focus and keep it in the tree.

## What was fixed

| Problem | Fix |
| --- | --- |
| Pages had no main region, and their content sat outside any landmark. | The page body is the main region. |
| Repository rows in the navigation had a spoken name that left out the visible count, and reference chips and rows named an item differently from their visible text. | The spoken name now contains the visible text. |
| Empty tiles and "nothing here" lines were faded with opacity and fell under 4.5:1 contrast. | They use the theme's secondary text colour at full strength. |
| The delegation timeline was marked as one picture while holding focusable parts. | It is a group. |
| Scrollable code blocks could not take focus, so their hidden lines were out of reach for the keyboard. | They take focus and scroll with the arrow keys. |
| A marketplace could be folded with the mouse only. | Its name takes focus and folds and unfolds with Enter or Space. |

## What is left

- The scan reads the page as it renders. It does not replace a test with a screen reader such as NVDA or VoiceOver.
- The scan and the walk cover pages in their opened state. A menu or a confirm card that opens only after a press is checked by the interface tests, not by the scan.
- The keyboard walk covers one page of each type, not every one of the 160 navigation pages. Pages of one type share their code.
- The heading of a marketplace is still a mouse target as a whole row. The keyboard folds it through its name.
